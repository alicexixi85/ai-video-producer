# Gemini Window Mastery — public v1.1

A generalized edition of a 2026-10-17 field notebook about Gemini web-window workflows. This is independent community guidance, **not official Google documentation**. Interface labels, product tiers, entitlements, model names and limits change: check the active account and current product UI rather than relying on this dated record.

## Start a session

1. Open the official Gemini web application. Check the account menu and active account; never assume a previously opened tab uses the expected account.
2. Prefer a clearly isolated browser profile per account where the current platform policies permit it. Verify profile and active session before consuming quotas.
3. Open the current model/feature selector and choose based on the task: a quick inexpensive mode for routine tasks, a more capable reasoning mode for complex writing or research, or the appropriate creative generation feature for image, music or video.
4. If the application has a usage/limits panel, record the current observed figures, reset times, task type and time zone. See `references/quota.md`.
5. For reproducible work, record the prompt, chosen mode, settings, output version and outcome.

## Choosing a workflow

- **Images:** follow `references/image-music-video.md` for mode selection, character/visual consistency, critical-frame regeneration and quality review.
- **Music:** draft a structured music brief in ordinary chat, then use an available music-generation feature and verify the saved audio asset.
- **Video:** set portrait format explicitly when available, capture the generated clip, then perform an output inspection; do not infer successful rendering from button clicks.
- **Production packs:** for story-to-production work, first ask the model to critique plot logic, continuity and shot feasibility, then save the generation artifacts incrementally.
- **Skills/features:** follow the UI exposed by your specific Gemini version; test the installed skill with a harmless example. If the advertised invocation syntax has changed, update your local instructions rather than assuming an old `@` or `/` convention still works.

## Budget and safety

- Do not repeat-submission-loop when a generation appears stuck; first inspect the existing job and UI state.
- Account quota claims must identify account alias (never publish real email), feature or model, the observed metric, reset time, and when it was observed. Avoid account-wide claims when only one feature is rate-limited.
- Paid API usage, subscription UI allowances, and developer tools are distinct products. Do not assume they share pricing, quotas, or capabilities. Obtain explicit user approval before enabling paid routes.
- Respect platform policies, copyright, privacy and consent. Do not publish credentials, account mappings, internal file IDs, or private generated content.
