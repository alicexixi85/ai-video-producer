# Safety, privacy and budget constraints

These are the **public, reusable equivalents** of the original v1 team's internal constraints. A source organization that chose not to use paid APIs does not impose that rule on all users.

- Do not use payment-enabled API calls without the current user's explicit cost authorization. Web subscriptions and API billing are distinct.
- Do not paste or commit secret values, cookies, authentication tokens, recovery codes, private project IDs or identifiable user-account data.
- Do not embed absolute paths from somebody else's machine or unpublished Drive document IDs in distributed Skills.
- Do not assume premium entitlement from a model name alone; verify in the current product UI.
- Do not bulk retry to bypass a rate limit or account restriction. Pause, capture the exact error and follow the service terms.
- Do not treat generated outputs as licensed for all uses automatically. Check commercial use, trademarks, depicted persons and required disclosures.
- Do not claim delivery until the media file is actually downloaded, inspected and playable.
